# LEARNINGS — operational traps (v3, seeded 2026-09-16; the v2 log is at docs/history/LEARNINGS-v2.md)

Append-only. One or two lines each: what bit, and the rule. Keep it to things a future run
needs; measurement narratives belong in docs/.

(LinkedIn and the Jobright reader are off in this public copy.)

- **Cloud image: LibreOffice.** The image ships `libreoffice-core`, whose `soffice` exists
  but cannot open a document. Guard on the Writer filter: `test -f
  /usr/lib/libreoffice/share/registry/writer.xcd || apt-get install -y libreoffice-writer`.
- **Cloud image: pypdf.** `import pypdf` fails with `No module named '_cffi_backend'` until
  `pip install --upgrade cffi`. Do it in STEP 0, unconditionally.
- **`RESUME_RENDERER=soffice` in every shell.** It does not persist across Bash calls.
- **soffice writes the shipped PDF; Word only cross-checks pages.** Word's PDF text layer
  sprays spaces inside compound words ("real -time"), which ATS parsers read. Never ship a
  Word-rendered PDF.
- **Bullet glyph font.** The template's bullet is U+2022 in Times New Roman on purpose;
  a Symbol-font bullet made Word paginate one line longer than LibreOffice for three weeks.
  `preflight.check_font_families` errors on any other family.
- **Two DB writers only.** The Actions cron and `sync.py`. A third writer produced
  unmergeable rebase conflicts on a committed binary. Routines write sidecars.
- **Routine prompt updates and `main` pushes are one step.** The next fire clones remote
  `main`; a prompt naming repo content that is not pushed runs against the old tree.
- **`RemoteTrigger` is main-thread only.** A subagent cannot load it. Do the fetch, the
  update and the read-back in the main session, and verify with `routine_parity.py`.
- **Never checkout `applications/` wholesale from a branch.** Take only folders absent
  locally and vouched for by a `tailored/<id>.json` on that branch, or a half-written
  folder freezes on `main`.
- **A suspended cloud run is not a crashed one.** `status: active, worker_status: idle`
  with no report means a usage-limit suspension; resume it from claude.ai/code/routines.
- **GitHub cron delivery is unreliable** (measured 23-95% of fires). Two entries at :17 and
  :47 buy typical latency, not worst-case; a third buys nothing.
- **`git add` of a named path that no longer exists wedges sync's commit step.** Keep
  `stage_and_commit`'s path list in step with the tree.
- **The lint hook fires on Write/Edit only.** A script writing into `applications/` bypasses
  it; `screening_draft.py` self-lints for that reason.
- 2026-09-16: a local tailor run as a subagent while Claude Code is in /low-priority mode may never start (empty transcript, "stalled: no progress for 600s"). Run Phase 6 style local tailors at normal priority, or expect to relaunch.
- 2026-09-16: project agent types (`ats-scanner`, `recruiter-screen`, `hiring-manager`, `job-scorer`) are only registered when the Claude Code session starts in the repo root. Started one level up, `subagent_type` is "not found"; fall back to `general-purpose` with the agent file pasted verbatim and the model pinned (tailor.md says how). The cloud routine runs at the repo root, so it is unaffected.
- 2026-09-16: reviewer files are written incrementally; read a review only after its Agent tool result returns, never on file existence (a half-written score line shipped once in a test run before it was caught).
- 2026-09-16: preflight `check_page_fill` is advisory under two lines; chasing it against the 42-word bullet cap cost one run eleven render cycles. Preflight now errors on page count != 1 (it did not before).
- 2026-09-16: `preflight.py` shipped a NameError in its first check for about two hours (a local `from pypdf import PdfReader` was missing) and the fake-based tests could not see it; `test_preflight.py` now runs the real CLI on a rendered pair. Any new preflight check must import what it uses inside the function, like the others.
- 2026-09-16: a PDF open in Acrobat holds an exclusive lock; render, delete and rename all fail. One agent closed the Acrobat window to get past it. Never do that: write `<name>.new.pdf` and report. Reviewer files are now per round (`review-<kind>-r<N>.md`) because round 2 overwrote round 1's ATS file before review.md was assembled.

- 2026-09-18: a cloud routine run pushes only to the branch the session designates, which is the outcome branch plus a run suffix (`claude/judge-j99h5u`), never to `claude/judge` itself. `sync.py`, `dashboard.py`, `dashboard.yml` and the routine's STEP 2 treat `claude/judge*` as one family; sync deletes a run branch once folded. A watcher must poll the glob, not the bare name.
- **2026-09-21** - A title the record labels "official" can still be wrong, and the record is the thing parse-back trusts. When Vaish corrects a title, fix `record.json` first and let the resumes follow; correcting a resume without correcting the record leaves the next run free to reintroduce the old one.
- 2026-09-22: the cloud routine environment has no `fork` agent type (only the project agents plus Explore, Plan and general-purpose); a prompt that asks for one wastes a call per job. Per-job context isolation is not available there; measured runs tailor 8 jobs in about 57 minutes in one thread.
- 2026-09-22: Indeed filed a bank's posting under the company name of a sponsor forum, so `role_key` differed from the earlier posting of the same req and the routine tailored it twice. STEP 4 now also matches the normalized title against recent brief headings.
- 2026-09-22: a subagent killed by a session usage limit (HTTP 429) may already have written its output file; check the file before relaunching, and relaunch the audit on the page as it stands, not the page it was given.
- 2026-09-28: GitHub cron delivery measured at **12%** for 30 days (about 6 of 48 fires a day, gaps to 6.5h, median job age at detection 23h). Detection is now dispatched by cron-job.org every 2h (docs/schedule.md); the GitHub `schedule:` is a sparse backup. Do not add schedule entries back.
- 2026-09-28: judge-queue selection lives in `pipeline/worklist.py` (score / siblings / tailor). Change a selection rule there, with a test, never in the prompt prose.
- 2026-10-04: a push that dies outright (DNS down, 10-02) leaves sync's own commit local, and the next `pull --rebase` replays its jobs.sqlite onto the cron's newer one: the same binary conflict on every run, so aborting the rebase never helps. Sync was down 10-01 to 10-04. `drop_stranded_sync_commits()` now resets sync-only unpushed commits to origin/main before the pull; a mix with hand-made commits is parked on a rescue ref and stops loudly. When sync fails, read the tail of `pipeline/sync.log` before anything else.
- 2026-10-04: the template and master resume said Dartmouth ended November 2026 after Vaish set December 2026 (09-21), so parse-back's own suite failed for two weeks while every tailor quietly corrected it. A record.json change updates the template, the master md/docx/pdf and the test fixtures in the same commit.
- 2026-10-06: folding lived only on the laptop while detect.yml's age sweep runs every 2h in the cloud. With the laptop off 10-01 to 10-04, 32 reviewed resumes (25% of that week) were swept to stale_skip as unscored `new` rows, and the late fold refused them. Folding now runs in Actions on every routine push (`fold.yml`, `sync.py --ci`), and a tailor sidecar under 7 days old folds over an age sweep (never over a delisting). Any cloud stage that sweeps must not outrun the stage that folds.
- 2026-10-06: filter.py took the MINIMUM years figure in a JD, so additive bullets ("10 years PM" + "5 years launching") read as 5 and 25 of 25 7+-year JDs reached the scorer. Bullets are now additive (max); only figures joined by "or" on one line are alternative paths (min).
- 2026-10-06: uncommitted edits to tracked files on the laptop do not survive a sync window: the push-race recovery (`reset --hard origin/main`) wiped a session's knowledge edits. Commit before the next slot; if lost, `git fsck --unreachable` finds the pull autostash.
- 2026-10-08: laptop sync retired. With fold.yml folding first, the laptop's push-race recovery (`reset --hard`) would wipe uncommitted edits on most runs, and /mark and /tailor never pushed their DB writes at all. The laptop now writes only text records and publishes them (`pipeline/localgit.py`); a push to main carrying records triggers the fold. Never write jobs.sqlite on the laptop.
- 2026-10-08: JobSpy's LinkedIn search is relevance-ranked, so `results_wanted=25` with a 24h window re-read the same top 25 every 2h and added 1-7 rows a run while 56 of the top 100 "product manager" results were never seen. Read deep in a window of hours-since-last-run + 2, and fetch JD pages only for new rows; LinkedIn 429s parallel detail fetches, so keep 2 workers with backoff.
- 2026-10-08: Actions minutes ran ~75-99 billed a day against Pro's 3,000 a month, a third of it dashboard rebuilds as separate jobs (every detect, gated skips included). The publish is now a step inside detect.yml and fold.yml (`.github/actions/publish-dashboard`). Check `gh api users/vaishnav-16/settings/billing/usage` before adding scrape depth.
- 2026-10-08: LinkedIn's logged-out search ignores every sort parameter (sortBy=DD, sort=DD, the public page), and f_TPR is honoured to the minute but its window is a firehose ("product manager": 128 listings in 10 min). Indeed's GraphQL does accept `sort: DATE` (JobSpy hardcodes RELEVANCE) and its window is small (22 results in 2h), so Indeed is read to the end and LinkedIn by relevance. Jobright's app answers 403 / errorCode 43004 after ~20 quick requests; page it slowly. api.getro.com disallows crawling in robots.txt; read Getro boards through their own pages.
- 2026-10-08: Jobright app feed: read sortCondition=0 (Recommended, what Vaish sees). sortCondition=1 (newest) loosens the role match into a firehose of non-PM roles; it has no time edge, so read a fixed 5 pages and let dedupe work.
- 2026-10-08: since the laptop publishes text records to main, most detect push rejections are text-only laptop pushes. Re-scraping (~4 min) after each lost every retry while Vaish was committing (run 37845696361). detect.yml now replays its commit onto the new tip when the remote jobs.sqlite is unchanged, and re-detects only when the DB moved.
- 2026-10-09: `profile/network/` is outside the lint hook (it fires only under `applications/`) and the
  knowledge files are full of em-dashes, so content drafted from them picks them up. Import `RULES` and
  `DATE_RANGE` from `.claude/hooks/lint_generated.py` and run them over the content file before every
  publish; the rendered page itself is covered by `preflight.py`. `DATE_RANGE` wants "Present" capitalised.
  Also: a `publish` chained after an edit script with `;` committed another session's dirty file when the
  script failed (10-08); publish only after the edits succeeded, and name files, never a directory another
  session has dirty.
- 2026-10-09: `replace_paragraph_text` used to drop the template's bold labels and project names unless the text carried `**`; 26 of 35 pages on 10-07/08 shipped uneven. The engine now carries the bold lead-in, and preflight ERRORs on tailored pages (applications/) for a positioning line, a moved section, a plain label, a retired title, or a `retired_claims` match from record.json.
- 2026-10-09: an edit to a page after its review (a 10-08 re-title) leaves SCORES describing a page that no longer ships; note any post-review edit in review.md, or re-review.
- 2026-10-09: logged-out LinkedIn hides the "Reposted" tag and shows the repost time as the posting time; the job ID (issued in order, ~410K/day) is the tell. scrape.linkedin_reposts skips IDs trailing the run's newest by 1.2M+.
- 2026-10-09: Decide counted the scorer's own skip lane (166 of 451); db.set_score never closes a skip-laned row. The board now folds them into a collapsed group.
- 2026-10-09: in the soffice PDF, punctuation right after a bold run can vanish when the run ends a rendered line ("**$0 inference**."); preflight passes it but reviewers call the bullet broken. Rephrase so the bold run does not end the line.
- 2026-10-10: state codes in a case-insensitive regex match English words ("or" = Oregon, "in" = Indiana); scrape.US_SIGNAL matches codes upper case only. Placeless locations ("Hybrid", "North America") are unknown and kept.
- 2026-10-10: beside a foreign place a bare state code is often a country prefix (Workday "IN - Bengaluru, India" read as Indiana); scrape.foreign_only counts a code there only as "City, ST".
- 2026-10-11: a re-score of an already-scored row must reach the DB, or the fold undoes it: `reconcile_sidecars` rewrites any sidecar whose lane disagrees with the DB, and ingest used to fold only an auto-tailor -> skip re-lane (the 10-10 re-score of 37 rows was reverted at 01:32Z). `ingest_scores.is_relane` now folds any lane change (promotions win). The same day a routine branch cloned before the fix carried the reverted copies (same `scored_at`) and its fold re-laned them back, so `sync.keep_newer_sidecars` now takes a score sidecar from a branch only if the branch added or changed it since its merge base with main. A re-score must still write a new `scored_at`.
- 2026-10-11 (corrects 09-22): per-job context isolation IS available in the cloud: a coordinator can launch a fresh `resume-tailorer` subagent per job and resume it with SendMessage, context intact. What is missing is nesting: a subagent gets no Agent tool (Claude Code 2.1.296, even with `Agent` in its definition), so the coordinator launches the reviewers and relays their files.
- 2026-10-11: a routine coordinator told to "save each scorer reply verbatim" re-typed them instead (score-queue, Sonnet: a shell helper rebuilding Total/GATES/STRETCH from memory, once hard-coding `GATES: none` for a batch). Anything a pipeline must keep verbatim is written by the subagent itself to a named file and ingested by code (`job-scorer` writes `/tmp/score-replies/<id>.md`; `ingest_scores.py record-dir`).
- 2026-10-12: a sentence ending ". Rephrase so no sentence break sits right before a bold run at a wrap, or read `extract_text` after the render.
- 2026-10-12: `localgit.py begin` stops on Vaish's own untracked files under applications/ (cover letters, q-*.txt), not only on half-run commands. When they are his, `git fetch` plus `git merge --ff-only origin/main` updates main safely; never publish or discard his files for him.
- 2026-10-13: a skip is one-way at the fold: it deletes queue/<id>.json and the score sidecar, the DB sheds the JD, and a tailor sidecar never folds over `skipped`. To undo one, restore both files from the commit before the fold (`git checkout <sha> -- queue/<id>.json scores/<id>.json`) and publish a `promote` entry with them; decisions.py revives a skipped row only when its queue file is back. A bulk triage should leave its close calls undecided rather than skip them.

The October pace (~3,100 of 3,000) came from dashboard clicks: each pushed pending.json 10s later and started a fold (81 on 10-12, ~190 min). A click now starts no workflow; detect dispatches a fold when `decisions.py --foldable` says so. Any longer decision window needs worklist.py to honour pending closes, or a skipped job still gets tailored.

Read floors by date and bucket across a cron change, or give it the old cron.
